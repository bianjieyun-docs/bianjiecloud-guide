# 智能分流、全局与直连怎么选：Clash 模式和 TUN 接管范围说明

## 一句话结论

日常使用优先选择“智能分流 / 规则”模式；只有在特定海外网站被误判为直连、或需要临时排查分流问题时，才切换到“全局代理”；“直连”适合临时停用代理，而“系统代理”和“TUN”则决定哪些软件的流量能够被客户端接管，两者不是同一组开关。

## 适用场景

本文适合以下情况：

- 第一次使用边界云加速，不清楚“规则、全局、直连”应该怎么选；
- 在 Clash Verge Rev 等 Clash 客户端中，看到“规则模式”和“TUN 模式”后容易混淆；
- 浏览器可以访问，但游戏、终端、命令行工具或其他应用没有经过代理；
- 某个海外站点在智能分流下打不开，需要判断是规则问题、系统代理问题还是接管范围问题；
- 希望在不中断客户端的情况下，暂时恢复所有应用的直连访问。

本文讨论的是流量处理逻辑，不涉及线路测速、节点速度或在线率统计。

## 一、先区分两组设置

代理客户端通常同时提供两类设置。第一类是“流量模式”，决定已经进入代理内核的请求如何处理；第二类是“接管方式”，决定哪些应用的网络请求能够进入代理内核。

### 1. 流量模式：规则、全局、直连

在官方客户端中，这些选项可能显示为“智能分流、全局代理、直连”；在 Clash 客户端中通常对应“Rule、Global、Direct”。它们控制的是请求进入内核后的去向。

| 流量模式 | Clash 中常见名称 | 处理方式 | 适用场景 |
| --- | --- | --- | --- |
| 智能分流 | Rule / 规则 | 按域名、IP、规则集等判断，国内网站直连，海外网站使用代理 | 日常浏览、办公和大多数应用 |
| 全局代理 | Global / 全局 | 默认让请求通过当前选择的代理策略或节点 | 某个站点在规则模式下打不开时临时排查 |
| 直连模式 | Direct / 直连 | 请求不经过代理线路，直接访问目标地址 | 临时停用代理、测试本地网络或访问国内服务 |

规则模式的实际结果取决于当前配置中的规则和策略组，并不是所有软件都使用完全相同的国内外判断标准。Clash Verge Rev 的官方文档也说明，自定义规则会按顺序匹配，命中第一条符合条件的规则后停止，因此规则顺序会影响最终结果。([github.com](https://github.com/clash-verge-rev/clash-verge-rev.github.io/blob/main/docs/guide/rules.md))

### 2. 接管方式：系统代理和 TUN

“系统代理”和“TUN”不是“规则、全局、直连”的替代名称，而是另一层设置。

- **系统代理**：修改操作系统的 HTTP、HTTPS 或 SOCKS 代理设置。浏览器和大多数遵循系统代理的软件可以使用它，但部分游戏、终端程序、后台服务或自带网络栈的应用可能不会读取系统代理。
- **TUN 模式**：创建虚拟网络接口，并在系统网络层接管更多流量。它适合不读取系统代理的应用，但通常需要管理员权限、服务模式或系统授权。Clash Verge Rev 的设置说明将 TUN 描述为虚拟网卡模式，启用后通常不再需要单独打开系统代理。([github.com](https://github.com/clash-verge-rev/clash-verge-rev/blob/dev/src/locales/en/settings.json))

TUN 只解决“流量是否进入内核”的问题，进入内核后仍然要按照规则、全局或直连模式处理。也就是说，TUN 不等于全局代理；可以使用“TUN + 规则”，也可以使用“TUN + 全局”。

## 二、日常使用：选择智能分流 / 规则模式

### 第 1 步：导入并启用配置

以 Clash Verge Rev 为例，先在 Profiles 或“配置”页面导入有效订阅，等待配置文件加载完成，再进入代理页面选择策略组。Clash Verge Rev 项目源码和发行版本可从其官方 GitHub 仓库获取，第三方下载页面不在本文推荐范围内。

如果你使用的是边界云加速，完成订阅导入后，建议先保持默认的规则或智能分流模式，不要一开始就切换全局。这样可以让符合直连规则的请求直接访问，其他请求再按照配置进入代理策略。

### 第 2 步：打开系统代理

对于主要使用浏览器、办公软件和常见桌面应用的场景，可以先打开系统代理。打开后检查客户端状态栏或系统网络设置，确认代理开关已经生效。

如果浏览器能访问目标网站，而某个独立应用仍然无法访问，不要立即判断节点不可用。更常见的原因是该应用没有读取系统代理，此时可以继续阅读下一节，判断是否需要 TUN 模式。

### 第 3 步：保持规则模式

在代理模式中选择“规则 / Rule”。如果配置包含代理策略组，确保策略组已经选择可用的代理出口；如果某个域名被配置为 DIRECT，它就会绕过代理，即使当前启用了系统代理。

规则模式通常更适合长期使用，原因包括：

1. 国内网站不需要绕行代理线路，访问路径更直接；
2. 不需要代理的流量不会占用代理服务的用量；
3. 国内银行、支付和企业系统通常更容易维持本地网络环境；
4. 只有匹配到代理规则的请求才会进入相应策略，减少不必要的干扰。

## 三、单个海外网站打不开：临时切换全局排查

当某个海外网站在规则模式下打不开，可以按以下顺序排查：

1. 确认客户端已经启用配置，代理策略组不是空组或未选择状态；
2. 临时切换到“全局 / Global”；
3. 重新打开目标网站，或使用无痕窗口测试；
4. 如果全局模式可以访问，说明问题更可能与域名规则、规则集更新或 DNS 解析结果有关；
5. 测试完成后切回“规则 / 智能分流”。

全局模式下，国内网站也可能经由代理策略访问，因此它适合短时间定位问题，不建议作为长期默认模式。全局模式能够访问，并不代表所有规则都错误；也可能只是目标域名没有被当前规则集正确归类。

如果需要长期固定某个域名的处理方式，应优先使用客户端支持的自定义规则功能，而不是一直保持全局。Clash Verge Rev 官方文档提供了 DOMAIN、DOMAIN-SUFFIX、IP-CIDR 等规则类型示例，例如：

```text
DOMAIN-SUFFIX,example.com,代理策略
DOMAIN-SUFFIX,example.cn,DIRECT
```

其中“代理策略”需要替换成当前配置中真实存在的策略组名称，不能直接照抄为一个不存在的组名。自定义规则通常还需要注意匹配顺序：如果前面已经有更宽泛的规则，后面的新增规则可能不会被执行。

## 四、游戏、终端或命令行工具不走代理：考虑 TUN

如果浏览器已经可以正常访问，但游戏启动器、Git、终端、脚本运行环境或其他不读取系统代理的软件仍然直连，可以考虑开启 TUN 模式。

### 操作步骤

1. 先确认配置文件已经成功加载，并选择好规则或全局模式；
2. 在客户端设置中找到 TUN、服务模式或管理员权限相关选项；
3. 按系统提示授权。Windows 和 macOS 上，创建系统级虚拟网络接口通常需要管理员授权；
4. 开启 TUN 后，观察客户端日志和目标应用行为；
5. 如果只是希望海外应用按规则分流，使用“TUN + 规则”，不要因为开启 TUN 就自动切换到全局；
6. 使用完毕后，优先从客户端关闭 TUN，再退出客户端，避免系统代理或虚拟接口残留。

mihomo 官方文档列出了 TUN 的 `auto-route`、`auto-detect-interface`、`strict-route` 和 DNS 处理等选项；不同客户端可能通过图形界面生成这些配置，因此不建议把其他版本或其他客户端的完整 TUN 配置直接复制过来。([github.com](https://github.com/MetaCubeX/Meta-Docs/blob/main/docs/config/inbound/tun.en.md))

需要注意的是，TUN 可能改变更多应用的网络路径，也可能与企业 VPN、虚拟机、网络安全软件、局域网共享或其他 VPN 应用产生冲突。如果开启后出现内网不可访问、应用无法联网或系统网络异常，应先关闭 TUN，恢复到系统代理或直连方式，再逐项排查。

## 五、如何判断当前模式是否真的生效

不要用 `ping` 或 `tracert` 直接判断代理线路是否生效。ICMP 请求通常不遵循浏览器的 HTTP/SOCKS 系统代理；在 TUN 模式下，内核还可能对部分 ICMP 流量进行本地处理，因此它们不能代表网页请求的实际代理路径。

更可靠的做法是使用应用层验证：

- 在浏览器中访问目标网站，查看页面是否能够正常加载；
- 使用客户端连接日志，观察目标域名命中的规则和最终策略；
- 对于命令行工具，确认该工具是否支持 HTTP_PROXY、HTTPS_PROXY 或 SOCKS5 配置；
- 在 PowerShell 中查看当前会话的代理环境变量：

```powershell
Get-ChildItem Env: | Where-Object { $_.Name -match '^(HTTP|HTTPS|ALL|NO)_PROXY$' }
```

- 在 macOS 或 Linux 中查看环境变量：

```bash
env | grep -Ei '^(http|https|all|no)_proxy='
```

环境变量为空，并不一定表示客户端没有代理；它只说明当前命令行会话没有设置环境变量。若应用不支持系统代理或环境变量，TUN 才可能覆盖到该应用的网络请求。

## 常见问题

### 1. 规则、全局、直连和 TUN 有什么关系？

规则、全局、直连决定请求进入内核后如何选择出口；TUN 决定更多系统流量能否进入内核。两者可以组合使用，例如“系统代理 + 规则”适合浏览器，“TUN + 规则”适合需要接管更多应用的场景。

### 2. 为什么全局模式能打开，规则模式打不开？

通常说明当前域名没有命中预期的代理规则，或者命中了 DIRECT、REJECT 等其他规则。可以先用全局模式确认基础连接，再检查域名规则、规则集更新状态和策略组选择。自定义规则应放在合适的优先级位置，并使用当前配置实际存在的策略组名称。

### 3. 打开系统代理后，游戏还是直连，怎么办？

很多游戏、启动器、终端工具或后台服务不会读取系统代理。先确认应用本身是否支持 HTTP/SOCKS5 代理；如果不支持，可以尝试开启 TUN。开启 TUN 前应确认客户端已经加载配置，并准备好管理员权限或系统授权。

### 4. TUN 模式是不是必须配合全局代理？

不是。TUN 只是扩大流量接管范围，接管后的流量仍然可以使用规则分流。日常更推荐“TUN + 规则”；只有在排查某个站点的规则匹配问题时，才短时间尝试“TUN + 全局”。

### 5. 直连模式和关闭客户端有什么区别？

直连模式通常表示客户端仍在运行，但流量不经过代理线路；关闭客户端则可能同时停止系统代理、TUN 接管和本地代理端口。临时停用时可以使用直连，遇到系统网络状态异常时再完全退出客户端并检查系统代理开关。

### 6. TUN 开启后出现内网或企业 VPN 异常怎么办？

先关闭 TUN，恢复系统代理或直连，确认问题是否消失。若确定是路由冲突，再根据客户端和内核版本检查局域网排除、默认网卡、严格路由以及企业 VPN 的兼容要求；不同系统和版本的字段名称可能不同，应以对应项目的官方文档为准。
