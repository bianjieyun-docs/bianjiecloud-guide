# Clash Verge Rev 订阅导入失败（client error Connect）排查教程

**一句话结论：** Clash Verge Rev 出现 `client error(Connect)` 时，不要先反复切换节点，应先确认订阅链接本身可访问，再按“客户端版本 → 导入方式 → 证书 → DNS/网络 → 配置和代理状态”的顺序排查；如果浏览器也无法打开订阅地址，问题通常不在 Clash Verge Rev 的节点选择页面。

## 适用场景

本文适用于 Windows、macOS 或 Linux 上使用 Clash Verge Rev 时遇到以下情况：

- 在“订阅”或 Profiles 页面添加远程订阅后提示 `client error(Connect)`；
- 订阅名称已经出现，但更新时间没有变化，配置内容为空或节点列表没有更新；
- 浏览器可以正常访问普通网站，但 Clash Verge Rev 无法下载订阅；
- 远程订阅始终失败，需要先下载配置文件，再通过本地文件导入；
- 配置导入成功，但启用系统代理后浏览器仍无法访问目标网站。

Clash Verge Rev 的官方文档说明，远程订阅支持“订阅链接导入”“订阅链接配置”和 URL Schemes 等方式；当“订阅链接导入”提示 `client error(Connect)` 时，可以尝试其他导入方式。官方文档还说明，本地配置支持新建配置文件和拖拽配置文件两种导入方法，拖拽配置文件需要较新的 Clash Verge Rev 版本。([github.com](https://github.com/clash-verge-rev/clash-verge-rev.github.io/blob/main/docs/guide/profile.md))

## 分步骤排查

### 第 1 步：确认使用的是官方发布版本

先从 Clash Verge Rev 官方 GitHub 仓库的 Releases 页面获取安装包，不要从不明网盘、二次打包站点或搜索结果中的广告页面下载。官方发布页会按操作系统区分 Windows、macOS 和 Linux 安装包，并列出对应的架构版本。([github.com](https://github.com/clash-verge-rev/clash-verge-rev/releases))

安装后打开“设置”或“关于”页面，记录当前版本。若版本较旧，建议先备份本地配置，再从官方 Releases 页面更新。更新客户端的目的不是保证订阅一定可用，而是排除旧版本在系统代理、TUN、服务模式或订阅页面上的兼容问题。官方发布记录也显示，项目会持续修复订阅、系统代理、内核启动、DNS 和平台服务相关问题。([github.com](https://github.com/clash-verge-rev/clash-verge-rev/releases))

### 第 2 步：确认复制的是完整订阅链接

在服务商后台复制订阅地址时，注意以下细节：

1. 从链接开头的 `https://`/ 或 `http://`/ 开始完整复制；
2. 不要把链接前后的空格、换行符或中文标点一起复制；
3. 不要把网页登录地址误当成订阅地址；
4. 不要在公开聊天、工单截图或代码仓库中暴露订阅链接，因为订阅链接通常包含账户识别信息；
5. 如果服务商提供了多个客户端格式，选择 Clash、Clash Meta 或 Mihomo 兼容格式，而不是直接选择 sing-box、V2Ray 或 Shadowrocket 专用格式。

在浏览器地址栏粘贴订阅链接并访问一次。浏览器可能直接下载 YAML、JSON 或文本文件，也可能显示一段配置内容。只要浏览器明确返回超时、连接被拒绝、证书错误、401/403 或 404，就应先处理订阅地址、账户权限或网络访问问题，而不是在 Clash Verge Rev 中继续测速。

如果你使用的是边界云加速器，请在对应账户后台重新复制当前客户端格式的订阅链接，再回到 Clash Verge Rev 进行导入；不要手动修改链接中的参数或域名。

### 第 3 步：按官方支持的方式重新导入

#### 方式 A：订阅链接导入

在 Clash Verge Rev 中进入“订阅”页面，使用远程订阅输入框粘贴完整 URL，然后保存或导入。等待下载完成后，检查配置卡片中的更新时间、文件大小或配置状态。仅看到一个订阅名称并不等于下载成功，最好确认更新时间发生变化，并进入代理页面查看节点或策略组。

#### 方式 B：订阅链接配置

如果方式 A 报 `client error(Connect)`，切换到“订阅链接配置”方式重新添加。官方文档明确给出了这一排查方向：如果该方式仍然提示连接错误，可以尝试勾选“允许无效证书（危险）”后保存重试。([github.com](https://github.com/clash-verge-rev/clash-verge-rev.github.io/blob/main/docs/guide/profile.md))

“允许无效证书”会降低 TLS 证书校验安全性，只建议用于确认问题是否与证书链有关。测试完成后，应优先修复系统时间、系统根证书、网络代理或订阅服务端证书问题，并关闭该选项；不要把它当作长期默认设置。

#### 方式 C：先下载，再导入本地配置

如果浏览器能够下载订阅文件，但客户端直接请求失败，可以先在浏览器中保存文件，例如保存为 `config.yaml`，然后在 Clash Verge Rev 的“订阅”页面选择“新建”或本地配置导入，选中该文件并保存。官方文档说明，本地配置支持选择文件导入，也支持拖拽配置文件；导入时客户端会将配置复制到自己的 profiles 目录，因此原文件后续移动或删除通常不会影响已经导入的副本。([github.com](https://github.com/clash-verge-rev/clash-verge-rev.github.io/blob/main/docs/guide/profile.md))

如果文件下载后扩展名变成 `.txt`，不要只看扩展名判断格式。用文本编辑器打开文件，确认内容确实是 YAML 或 JSON 配置，而不是登录页面、验证码页面、HTML 错误页或一段“访问被拒绝”的提示。若文件第一行出现 `<html>`、`<!DOCTYPE` 或登录表单内容，它就不是有效的 Clash 配置文件。

### 第 4 步：用系统工具区分 DNS、线路和服务端问题

在 Windows 中打开 PowerShell 或命令提示符，执行：

```powershell
nslookup 你的订阅域名
ping 你的订阅域名
tracert 你的订阅域名
```

在 macOS 或 Linux 的终端执行：

```bash
nslookup 你的订阅域名
ping -c 4 你的订阅域名
traceroute 你的订阅域名
```

将“你的订阅域名”替换为订阅 URL 中的域名，不要把完整 URL 直接作为 `ping` 参数。可以按以下方式理解结果：

- `nslookup` 无法返回地址：优先检查 DNS、域名拼写、局域网 DNS 或域名服务状态；
- DNS 能解析，但浏览器和客户端都超时：可能是当前网络到该域名的连接受限、线路不通或服务端没有响应；
- 浏览器能下载、Clash Verge Rev 不能下载：重点检查客户端导入方式、系统代理、证书校验和软件版本；
- 浏览器返回 401 或 403：通常需要重新登录服务商账户、刷新授权或重新生成订阅链接；
- `traceroute` 或 `tracert` 中出现星号：单个中间节点不响应 ICMP 并不能单独证明线路中断，应结合浏览器访问和实际下载结果判断。

### 第 5 步：检查系统代理是否真正启用

订阅导入成功后，还需要在“代理”页面选择一个具体节点或策略组，再到“设置”中开启系统代理。只导入配置、不选择节点或不开启系统代理，浏览器通常仍会使用原来的网络连接。

建议采用以下顺序验证：

1. 在代理页面选择一个具体节点，不要只停留在空的策略组；
2. 开启系统代理；
3. 打开“连接”或 Connections 页面；
4. 在浏览器访问一个测试网站；
5. 回到连接记录，确认是否出现对应域名、请求状态和使用的策略组；
6. 如果请求没有出现在连接记录中，说明浏览器可能没有使用 Clash Verge Rev 的系统代理；
7. 如果请求出现但失败，再检查节点、DNS、规则或远端服务状态。

如果开启系统代理后所有网站都无法访问，可以先关闭 TUN、服务模式或其他 VPN/代理软件，避免多个程序同时修改系统代理、路由表或 DNS。排查完成后再逐项开启，不要一次性同时更改多个网络开关。

## 常见问题

### 1. 浏览器打不开订阅链接，是不是 Clash Verge Rev 的问题？

通常不能直接这样判断。先用浏览器访问订阅 URL：如果浏览器同样超时、返回 401/403、证书错误或下载的是 HTML 错误页，说明需要先检查订阅地址、账户授权、域名解析和当前网络。只有浏览器可以正常下载有效配置，而 Clash Verge Rev 仍报 `client error(Connect)` 时，才更适合重点排查客户端导入方式、证书选项和本地代理环境。

### 2. 勾选“允许无效证书”后可以导入，是否可以一直开启？

不建议。该选项会放宽证书校验，只适合用于确认“连接失败是否与证书校验有关”。确认原因后，应优先恢复正常证书校验，并检查系统日期时间、系统根证书、网络劫持、企业代理或服务端证书配置。官方文档将该选项列为连接错误时的尝试方法，但并未将其作为长期推荐配置。([github.com](https://github.com/clash-verge-rev/clash-verge-rev.github.io/blob/main/docs/guide/profile.md))

### 3. 订阅卡片显示成功，但代理页面没有节点，怎么办？

先检查配置文件是否真正完成更新，而不是只创建了一个空的 Profile。重新执行一次更新，确认更新时间和文件大小发生变化；然后用文本编辑器检查本地配置文件是否包含节点、代理组或出站配置。如果下载文件实际是登录页、错误页或空文件，需重新登录服务商后台并复制正确的客户端订阅链接。

### 4. 导入本地 YAML 后提示格式错误，如何判断文件是否有效？

先确认文件不是 HTML、JSON 错误响应或截断内容。YAML 对缩进非常敏感，不要用会自动替换空格的编辑器批量格式化；也不要随意删除引号、冒号或缩进。若配置由服务商生成，优先重新下载一份原始文件，而不是手动修复。修改前应保留备份，并避免将包含订阅信息的配置文件上传到公共代码仓库。

### 5. 节点能测速，但打开网页仍然失败，问题在哪里？

测速成功只能说明某类测试请求获得了响应，不代表所有域名、DNS 请求和网页协议都正常。检查连接记录中实际失败的域名，再分别判断是 DNS 解析失败、规则走了直连、策略组选择错误、节点不支持目标服务，还是目标网站本身拒绝访问。必要时临时使用明确的单节点和全局模式进行对照测试；测试完成后恢复适合日常使用的规则模式。

### 6. Windows 和 macOS 的排查重点有什么不同？

Windows 需要额外关注系统代理权限、服务模式、杀毒软件拦截和系统代理被其他软件覆盖；macOS 则需要关注系统扩展、网络过滤器、VPN 配置以及应用对网络权限的请求。无论平台如何，先确认“订阅是否下载成功”，再确认“节点是否选中”，最后确认“浏览器是否使用系统代理”，这样比直接反复更换节点更容易定位问题。
