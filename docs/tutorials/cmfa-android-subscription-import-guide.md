# CMFA 安卓订阅导入与自动更新教程

**一句话结论：**在 Android 手机上使用 Clash Meta for Android（简称 CMFA）时，先从可信来源安装应用，再将订阅格式选择为 `clash_meta`，通过“从 URL 导入”添加配置，选中配置后启动 VPN，即可使用规则分流和代理节点。

## 适用场景

本文适合以下情况：

- 想在 Android 手机上使用开源 Clash 客户端；
- 需要自行管理订阅、配置文件和代理策略；
- 已经拥有边界云订阅，但不知道如何导入 CMFA；
- 通过“一键导入”失败，希望手动添加订阅；
- 配置导入后没有线路、启动失败，或应用在后台一段时间后断开。

CMFA 是 Android 平台上的图形化 Clash 客户端，项目由 MetaCubeX 维护，底层使用 Mihomo 相关能力，并通过 Android VPN 接口接管系统应用流量。项目源码和发行版应以其官方 GitHub 仓库及 Releases 页面为准，不建议从来源不明的网站下载修改版 APK。

## 一、下载安装 CMFA

### 1. 从可信来源获取安装包

边界云官网的下载页通常会提供“其他接入方式”或 Android Clash Meta 入口，也可以直接前往 CMFA 官方 GitHub 仓库的 Releases 页面查看发行文件：

- [CMFA 官方 GitHub 仓库](https://github.com/MetaCubeX/ClashMetaForAndroid)
- [CMFA 官方 Releases 页面](https://github.com/MetaCubeX/ClashMetaForAndroid/releases)

下载前先确认发布页中的版本、文件名和说明。不同手机的处理器架构可能不同，绝大多数近年 Android 手机使用 `arm64-v8a`，但不要仅凭手机品牌或外观判断。若安装包提示“解析失败”“应用未安装”或架构不兼容，应回到官方发布页核对对应 APK，而不是随意安装其他来源的文件。

### 2. 允许安装并完成首次启动

如果 APK 是使用浏览器下载的，Android 可能要求允许当前浏览器安装未知来源应用。只在确认下载来源可信时开启该权限，安装完成后可以关闭浏览器的“允许安装未知应用”权限。

首次打开 CMFA 时，应用可能请求通知、文件访问或创建 VPN 连接等系统权限。VPN 权限用于让应用接管符合配置规则的网络流量，属于正常流程；应阅读系统提示后再决定是否授权。

## 二、复制边界云订阅链接

1. 使用手机浏览器登录边界云用户中心。
2. 进入订阅详情或订阅管理页面。
3. 在订阅格式中选择 `clash_meta`。
4. 点击“复制”获取订阅链接。
5. 暂时不要把订阅链接发送到公开群组、工单截图或社交平台。

订阅链接通常包含账户识别信息或访问凭据。任何拿到链接的人，都可能在有效期内请求配置，因此应像保护密码一样保护订阅地址。如果链接已经公开，优先在用户中心执行重置、刷新或重新生成订阅链接；具体入口以账户页面实际显示为准。

## 三、在 CMFA 中通过 URL 导入配置

### 方法 A：使用网页“一键导入”

在手机浏览器打开订阅详情页时，如果页面显示“一键导入”按钮，可以点击该按钮，系统会尝试唤起 CMFA 并添加配置。

如果手机没有正确关联应用、浏览器阻止跳转，或者点击后没有反应，可以改用下面的手动导入方法。两种方式的目标相同，都是把订阅 URL 添加到 CMFA 的配置列表中。

### 方法 B：手动从 URL 导入

1. 打开 CMFA，进入底部或侧边栏中的“配置”页面。
2. 点击右上角的“+”。
3. 选择“从 URL 导入”。
4. 在“名称”中填写便于识别的名称，例如：

   ```text
   边界云
   ```

5. 在 URL 输入框中粘贴刚才复制的 `clash_meta` 订阅链接。
6. “自动更新”可以填写：

   ```text
   1440
   ```

   这里的单位是分钟，`1440` 分钟约等于 24 小时。自动更新只负责定期重新获取配置，不等于应用会自动启动 VPN；如果订阅失效、网络不可达或服务端返回错误，更新仍可能失败。

7. 点击右上角的保存图标。

保存后，配置会出现在配置列表中。回到列表，点击刚刚添加的配置，使其处于选中状态。仅仅保存配置并不代表已经连接，仍需继续执行启动步骤。

## 四、启动 VPN 并选择线路

1. 回到 CMFA 首页。
2. 点击显示“已停止”的服务卡片或启动按钮。
3. 第一次启动时，Android 会弹出创建 VPN 连接的系统确认框。
4. 阅读提示后点击“确定”或系统对应的确认按钮。
5. 当首页状态变为“运行中”后，说明 CMFA 的本地 VPN 服务已经启动。
6. 进入“代理”页面，根据用途选择可用的代理组或线路。

启动后，Android 状态栏通常会出现 VPN 图标。这个图标只能说明系统 VPN 服务已建立，不能单独证明每个网站都能访问。如果某个应用仍无法连接，应结合 CMFA 日志、配置规则和目标应用的网络请求继续判断。

使用边界云订阅时，建议先确认配置已经成功更新，再启动 CMFA；如果配置中没有代理组或节点，重复点击启动按钮通常不能解决问题。

## 五、导入后如何确认配置有效

可以按以下顺序检查：

1. **配置列表中是否存在文件或 URL 配置。**如果列表为空，说明保存动作没有完成，重新执行“从 URL 导入”。
2. **配置是否处于选中状态。**未选中的配置不会作为当前运行配置。
3. **配置更新是否成功。**在配置右侧点击更新按钮，观察是否出现错误提示。
4. **代理页面是否有代理组或节点。**如果只有空白列表，重点检查订阅是否过期、流量是否用完，以及 URL 是否被截断。
5. **服务状态是否为“运行中”。**如果仍显示“已停止”，需要重新启动并处理 Android 的 VPN 授权提示。
6. **目标应用是否被规则设为直连。**规则模式下，不是所有域名都会走代理；可以查看代理组、规则匹配结果或应用日志进行判断。

## 常见问题

### 1. 导入后配置列表里没有线路，怎么办？

先回到“配置”页面，点击该配置右侧的更新按钮。如果更新失败，检查订阅 URL 是否完整、手机是否能正常打开其他网页，以及账户订阅是否到期或流量是否用完。

如果更新成功但仍没有线路，可能是订阅格式选择错误。CMFA 应使用适配 Clash Meta/Mihomo 的配置格式，边界云用户中心中对应的格式名称为 `clash_meta`。不要把 sing-box、v2rayN 或其他客户端专用格式直接当作 CMFA 配置导入。

### 2. 点击启动后没有 VPN 权限提示，怎么办？

先确认 CMFA 没有被系统强制停止，并检查 Android 设置中的 VPN、应用权限和后台运行权限。若之前选择过拒绝，可以进入系统设置重新打开应用，再回到 CMFA 尝试启动。

部分 Android 厂商会在系统管家、网络管理或安全中心中额外限制 VPN 服务。此时应检查该品牌系统的后台管理页面，允许 CMFA 在后台运行；设置名称会因 Android 版本和手机厂商而不同。

### 3. CMFA 后台运行一段时间后断开，如何处理？

Android 的省电策略可能限制应用在后台运行。可以进入系统设置中的“应用”或“电池”页面，找到 CMFA，允许后台使用，并根据手机系统提供的选项关闭对该应用的强制休眠或过度限制。

需要注意的是，关闭电池优化可能增加耗电量。Google 的 Android 帮助文档也说明，应用电池优化设置会影响后台运行和通知行为，因此应只对确实需要长期运行的应用调整，并观察耗电情况。

### 4. 订阅链接复制后，CMFA 提示 URL 无效怎么办？

常见原因包括：

- 复制时只复制了部分链接；
- 链接前后多了空格或换行；
- 浏览器复制的是网页地址，而不是订阅详情中的订阅 URL；
- 订阅已被重置，旧链接失效；
- 选择了不适用于 CMFA 的订阅格式。

可以删除当前配置后重新复制，并使用手机浏览器的“粘贴”功能检查 URL 是否完整。不要在公开环境中粘贴包含账户凭据的完整订阅地址。

### 5. 为什么已经显示“运行中”，某些应用仍然无法访问？

“运行中”表示 CMFA 的 VPN 服务已经启动，不代表所有应用请求都会自动通过代理。规则模式可能把部分域名、局域网地址或国内服务判定为直连，也可能存在应用自身的网络限制、DNS 缓存或证书校验问题。

建议先测试不同目标网站，再查看 CMFA 的代理日志和规则匹配结果。若只有某一个应用异常，优先检查该应用是否使用了独立网络设置、私有 DNS、代理绕过或系统级网络权限。

### 6. 是否可以把同一个订阅同时导入多个客户端？

通常可以，但每个客户端需要使用与自身内核兼容的订阅格式。例如，CMFA 使用 `clash_meta` 格式，sing-box 和 Shadowrocket 则应使用各自支持的配置或订阅格式。不同客户端的规则语法、协议支持和策略组表现可能不同，不能保证同一份配置在所有软件中完全一致。

同时使用多个客户端时，Android 通常只能有一个应用占用系统 VPN。切换客户端前，先停止当前正在运行的 VPN 服务，避免出现“无法建立 VPN”“服务冲突”或流量没有按预期转发的情况。
